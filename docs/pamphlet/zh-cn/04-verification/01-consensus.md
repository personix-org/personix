# 共识与验证过程

为了就"社会平均而言应当维护并执行哪些规则"建立共识,下面这个机制可以帮上忙。作为一个 DID 参与者,我宣告我所订阅、并将据以生活的规则,并把它们发布出来。(可以把它想象成在我看来构成我理想世界的那套章程与规约——一个我不感到受限、而是感到安全的世界。)

我可以预先估计我的 DID 联系人会作何反应——并评估,若那些寻常的社交或商业互动假设性地发生,我会以多大力度、被谁施加制裁。

真正决定性的评估,发生在你向另一个 DID 请求信息、或请它验证一条主张(或向某个权威请求一项服务,等等)——你想把这条主张发布到声誉网络时。它应当与你自己在演练中、对照对方所宣告政策所跑出的结果一致——如果不一致,那么对方那边就有问题:他们在试图玩一场不诚实的游戏。

结果要么是接受,并附上一个验证报价(在验证者或权威服务的情形下),要么是拒绝。对"偏离评估者政策"的制裁与奖励,都被折入报价之中。请求者随后决定:是接受这些条件,还是转入分配算法中的下一轮验证——不断重复这个过程,直到满意,或者直到经济上继续下去已无意义为止。

> [!note] 社交图谱
> 声誉网络首先是一个社交网络。你添加联系人——那些同意建立连接的人。他们有联系人,那些联系人又有联系人。算法在一个可配置的深度内(例如三层:你的直接联系人、他们的联系人,再往外一层)搜索验证者。不需要全球区块链——网络自然形成一个个共同体,并与其他共同体有所重叠。
>
> 算法是非确定性的:它对你的主张文档求哈希,把哈希映射到这个圈子内已知身份构成的环上的一个位置,并选出最近的一个作为候选验证者。你无法预测或影响谁将来验证你的主张。

每个验证者的拒绝都会扩大你的文档,并抬高它的处理成本——这是第一条成本通道(文档增长)。每个新的验证者都会根据数据量、你的声誉,以及你主张的内容偏离其所宣告验证政策的程度来收费——这是第二条成本通道(风险溢价)。而每一次迭代都花费时间和精力——这是第三条成本通道。

> [!note] 验证者依次检查什么
> 一旦被选中,验证者会大致按四个有序步骤评估一条主张——最便宜的过滤在先,昂贵的内容检查在后:
>
> 1. **政策门槛。** 这类主张是否落在验证者公开会验证的范围之内?若不在,请求当即被拒。
> 2. **权威信任。** 为该主张背书的权威,在验证者自己所宣告的政策之下是否足够可信?一个低于验证者信任阈值的权威,无论主张内容如何都构成拒绝的理由。
> 3. **发行者声誉。** 发行者是否达到验证者为此类主张所宣告的声誉阈值?低声誉可能要么抬高费用,要么触发拒绝。
> 4. **内容检查。** 只有当前三道门都通过时,验证者才评估主张本身——签名、内部一致性、形式正确性,以及它偏离验证者政策的程度。为这最后一步所收取的费用,反映了实际承担的风险。
>
> 验证者会发布规范上述每一道门的政策,因此这些步骤并非任由其自由裁量——它们受其已经宣告之内容的约束。偏离所发布的政策,本身就是一条可以针对他们发布的主张,而他们要用自己的声誉为此埋单。

结果是:发布一条可信而有用的主张,几乎不花什么钱。发布一条激进的主张,花费更多。发布一个谎言,则变得贵得令人却步——你必须一个接一个地迭代过验证者,而每一个拒绝你的人都会增加成本。市场为你的主张定价,而这个价格告诉你,你相对于你所身处的共同体处在什么位置。

仅仅宣告你遵守某条规则、而实际上并不遵守,是不够的。在那种情况下,你的 DID 就冒着被发布一条揭露伪善的负面记录的风险——这会把你变成对所有其他人的一个风险。其结果应当是:规则更少,但被更一贯地遵守,并清理掉那片连法律专业人士都几乎无从穿行的法律与法规的丛林。

> [!note] 共识与问责
> 为了让网络充当有价值的信息源,一个 DID 不应过于激进——否则其他人会拒绝它。社会压力会寻求均衡,而试图破坏这一均衡的行为很可能会受到惩罚。

> [!warning] 票数不等于一个声音的分量
> Juraj Karpiš 说"金钱是善行的记忆"。我要补充一句:声誉是恶行的记忆。
>
> 由此得出,在贤能政治的意义上,贡献更多且没有坏声誉的人,应当在共同体中拥有更大的声音分量。透过双边关系的视角来看:当我权衡该迁就哪些共识压力时,最大的分量归于那些让我获得最大经济利益的关系。十个我与之没有活跃交易往来的人,对我的影响远不如一个长期的生意伙伴。这一范式并不限于商业——它延伸到社会、政治及其他关系。
