# Огляд ролей

Деяких із цих ролей ми вже коротко торкнулися в розділі про мережу та її базові властивості. Тепер настав час поглянути на них знову докладніше й додати додаткові, які нам потрібні, щоб зробити мережу надійнішою. Кожна верифікаційна транзакція залучає кілька ролей — погляньмо, як вони поводяться.

> [!note] Ролі у верифікаційній транзакції
> Кожна верифікація залучає до шести окремих ролей, підсумованих у таблиці нижче. Усі вони можуть мати власний DID у децентралізованій репутаційній мережі.

| Роль | Опис |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Issuer** (видавець) | Особа, яка публікує інформацію в мережу — стверджує, що щось сталося (DID було створено, відредаговано чи розпущено, твердження, політика даного DID тощо) |
| **Subject** (суб'єкт) | Особа, якої стосується інформація — адресат твердження |
| **Authority** (авторитет) | Довірений суб'єкт, який ставить своє ім'я на якість твердження, розслідуючи його та або переглядаючи подані докази, або активно їх збираючи |
| **Observer** (спостерігач) | Незалежна третя сторона, яка веде запис того, як верифікатор поводиться з твердженням — стежачи, щоб верифікатор ні мовчав, ні відхилявся від задекларованої політики |
| **Verifier** (верифікатор) | Алгоритмічно обраний учасник, який опрацьовує транзакцію |
| **Delegate** (делегат) | Особа, що діє від імені іншого учасника |
