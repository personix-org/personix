# 역할 개관

우리는 네트워크와 그 기본 속성을 다룬 장에서 이미 이 역할들 중 일부를 간략히 짚었다. 이제 그것들을 더 자세히 다시 살피고, 네트워크를 더 견고하게 만드는 데 필요한 추가 역할들을 덧붙일 때다. 모든 검증 거래에는 여러 역할이 관여한다 — 그것들이 어떻게 행동하는지 보자.

> [!note] 검증 거래에서의 역할
> 각 검증에는 최대 여섯 개의 뚜렷한 역할이 관여하며, 아래 표에 요약되어 있다. 이 모두가 탈중앙화 평판 네트워크에서 자기만의 DID를 가질 수 있다.

| 역할 | 설명 |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **발행자(Issuer)** | 네트워크에 정보를 게시하는 사람 — 무언가 일어났다고 주장하는 클레임을 낸다(DID가 생성·수정·해소되었다, 어떤 클레임, 주어진 DID의 정책 등) |
| **대상자(Subject)** | 정보가 관한 사람 — 클레임의 수신자 |
| **권위자(Authority)** | 클레임을 조사하고, 제시된 증거를 검토하거나 능동적으로 수집하여 그 클레임의 품질에 자기 이름을 거는 신뢰받는 주체 |
| **관찰자(Observer)** | 검증자가 클레임을 어떻게 처리하는지 기록을 남기는 독립적 제3자 — 검증자가 침묵하지도, 자신이 선언한 정책에서 벗어나지도 않도록 확인한다 |
| **검증자(Verifier)** | 거래를 처리하는, 알고리즘으로 선정된 참여자 |
| **대리인(Delegate)** | 다른 참여자를 대신해 행동하는 사람 |
